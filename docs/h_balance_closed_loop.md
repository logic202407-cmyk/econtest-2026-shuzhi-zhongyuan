# H题小球平衡视觉与 X42S 闭环

## 1. 当前实现

H题平衡部分采用三级闭环：

```text
MaixCAM2 小球位置/速度测量
        |
        v
MSPM0 时间最优速度轨迹 + 状态估计 + 软限位
        |
        v
X42S 内部编码器位置闭环 + MSPM0 角度读回监控
```

新增入口：

| 功能 | 文件 |
| --- | --- |
| MaixCAM2 视觉程序 | `firmware/maixcam2/h_balance_vision.py` |
| H题控制器 | `application/balance/h_balance_control.c` |
| 独立控制参数 | `application/config/h_balance_config.h` |
| 主控二进制协议 | `application/vision/maixcam_protocol.c` |
| 扰动仿真 | `tools/control/h_balance_sim.py` |

旧云台算法不参与 H 题平衡控制。H题使用一台 X42S，默认电机 ID 为
`X42S_PITCH_MOTOR_ID`，即当前的 ID1。

## 2. 符号和机械方向

全链路统一使用以下定义：

- 管道 `0 cm` 位于升降电机端，位置从升降端向固定转轴端增加；
- X42S `CW`、角度增加：抬高升降端；
- X42S `CCW`、角度减小：降低升降端；
- 因此正电机角度使小球产生位置正方向加速度。

MaixCAM2 默认假定升降端位于图像右侧：

```python
LIFT_END_IS_IMAGE_RIGHT = True
```

如果相机画面中升降端实际在左侧，只修改该变量为 `False`。不要同时反转视觉坐标和
电机方向，否则会再次形成正反馈。

## 3. 视觉测量

视觉程序先用绿色 HSV 掩膜和旋转矩形确定管道的有向中心轴，连续 8 帧后锁定；再用
`/root/mymodels/demo03_test/best.mud` 的 YOLO26 类别 0 检测钢球。候选球必须位于管道
轴线附近，之后才投影为 `0~25 cm` 的一维位置。

速度不是相邻两帧直接相减，而是对最近 `45~130 ms` 的有效位置做带时间戳的线性
回归。检测跳变若意味着速度超过 `65 cm/s` 会被拒绝。UART 帧同时发送采集时间和
处理耗时，主控用速度将位置外推到当前控制时刻，降低 NPU 延迟造成的制动滞后。

数据帧固定 16 字节负载：

```text
seq:u16, capture_ms:u32,
position_0p01cm:i16, velocity_0p01cm_s:i16,
confidence_0p01pct:u16, processing_ms:u16,
flags:u8, source:u8
```

只有“检测有效、速度有效、管道已锁定、置信度合格”的连续数据才能进入运动控制。

## 4. 控制律

目标位置默认是管道中点 `12.50 cm`。目标速度由以下三项的最小值生成：

```text
最大速度限制
制动距离速度 sqrt(2 * 制动加速度 * 剩余距离)
近目标线性速度 Kx * 位置误差
```

随后速度误差转换为期望小球加速度，再利用实心球滚动模型
`a ≈ (5/7)g*sin(theta)` 转换为管道倾角。该连续轨迹没有“高速段/低速段”硬切换，
因此在视觉延迟变化时不易形成极限环。

当前安全起点：

| 参数 | 值 |
| --- | --- |
| 目标位置 | `12.50 cm` |
| 最大球速轨迹 | `16 cm/s` |
| 规划制动加速度 | `18 cm/s²` |
| 最大管道倾角 | `±5.0°` |
| 每 25 ms 最大倾角变化 | `0.5°` |
| 到位判据 | `±0.50 cm` 且 `|v|≤1.0 cm/s`，保持 500 ms |
| 视觉宽限/超时 | `90 ms / 180 ms` |
| 电机反馈超时 | `250 ms` |

控制器在靠近管道两端 `1 cm` 范围时直接覆盖普通控制律，强制向管道内部恢复。

## 5. 上板启动顺序

1. X42S 接线使用 `B12 -> TXD`、`B13 -> RXD`，自动方向模块不接 B14，所有电源共地。
2. 确认 ID1 在线，且手动命令已经验证 `CW/角度增加=抬高`。
3. 在 MaixCAM2 上运行 `h_balance_vision.py`，等待画面出现绿色管道轴线和 `LOCK 1`。
4. 手动把管道调到水平；这一步必须在按键前完成。
5. 按扩展板 `K1/PA26`。控制器先读取 X42S 编码器，把当前位置锁存为水平零点，然后
   使能电机；连续收到 3 帧合格视觉数据后才输出位置命令。
6. 再按一次 K1 可停止并退出闭环。B21 仍属于整车比赛计时/启停状态机，不用于本模块
   单独联调。

禁止在管道未调平、球不在画面、管道未锁定或机械端点没有防护时按 K1。

## 6. 串口状态

主控 UART0 的关键日志：

```text
VISION,BALL,VALID,1,...
BAL,STATE,<state>,FAULT,<fault>,TGT,...,POS,...,VEL,...,TILT,...
```

状态编号：

| 编号 | 含义 |
| --- | --- |
| 0 | 未使能 |
| 1 | 等待 X42S 编码器回复并锁存水平零点 |
| 2 | 等待连续有效视觉帧 |
| 3 | 正在控制 |
| 4 | 已稳定到位 |
| 5 | 视觉丢失，回水平保持 |
| 6 | 故障停止，需要重新按 K1 |

故障包括启动无编码器回复、电机反馈超时、电机角度超过零点 `±5.8°` 和非法目标位置。

## 7. 验证与整定边界

Host 测试验证了协议、方向、制动、边缘恢复、显式使能和失视觉回水平。扰动仿真对
30~100 ms 视觉延迟、40~140 ms 电机时间常数、65%~120% 机构增益和不同起点进行
500 组测试，当前模型结果为 500/500 不越界，稳定时间中位数约 2.10 s，95 分位约
3.11 s。

这些数字是设计仿真，不是实物成绩。实物第一次闭环必须保留 `±5°` 限制，按以下顺序
一次只调一个量：

1. 先确认坐标和 CW 符号；若球越跑越远，立即断电并检查视觉升降端定义。
2. 若接近目标后过冲，先降低 `H_BALANCE_PROFILE_MAX_VEL_0P01CM_S`，再降低制动加速度。
3. 若全程响应太慢且没有过冲，再小幅提高最大速度，保持制动曲线不变。
4. 若停在目标附近但有固定偏差，只调积分项，不先加大速度环增益。
5. 记录实物到位时间、最大过冲、稳态误差和电机最大角度后，才能扩大倾角范围。

运行仿真：

```powershell
python .\tools\control\h_balance_sim.py --cases 500 --seed 0
```
